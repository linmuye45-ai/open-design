# RESONANCE 共振

一款**颜色链式消除 + roguelike 构筑**的方块解谜游戏。

零运行时依赖，零构建步骤。8 个 JS 文件、1 个 HTML、1 个 CSS，加起来就是全部。
没有 webpack、没有框架、没有 npm install。

```bash
cd games/resonance
python3 -m http.server 8080     # 打开 http://localhost:8080
```

就这样，已经可以玩了。

---

## 这是什么

方块消除的骨架，但每个格子有颜色。落子后**同色相邻的格子会共振扩散**，
连锁越长倍率越高。每过一关从 3 件遗物里选 1 件，29 件遗物任意组合
（约 48 万种可能构筑），于是每一局的打法都不一样。

走完 18 关是通关（**终章**）。这个数字不是拍的——实测技巧 0.70 档到达率
0%、0.80 档 8%、0.90 档 6%，无人越过 19 关，所以它是"够得着但要运气配合"。
通关不强制结束对局：想继续刷分就继续，第 19 关起进入实质无尽。

参照系是 Block Blast 的手感与极简，和 Balatro 的构筑深度。

### 设计上的一条硬底线：每一局都是种子的纯函数

所有随机都来自可复现的种子（xmur3 → mulberry32，按用途分流）。
同一个种子，同样的操作，必然得到同样的结果。

这条约束带来两个后果，而它们都是有意的：

1. **不存在"暗中调难度"**。同类游戏常在玩家连败后偷偷发好牌
   （所谓 God Mode），短期留存有效，代价是一旦被发现，"这游戏在操控我"
   的指控就再也洗不掉。本作宁可放弃这个手段。
2. **激励视频不能改变结果**。所以看广告只能换"提示"和"重摇遗物"，
   不能换复活、不能换更好的牌。这不是配置项，是 `src/platform.js` 里的
   硬编码白名单，`test.js` 有断言钉住它。

安全网的做法是公开的：调音师机制（棋盘逼近死局时保证发一张放得下的牌）
额度、阈值、冷却全部是公开常量，玩家能在图鉴里看到。
**能被看见的仁慈不叫操控。**

## 部署

完整部署手册见 **[`docs/DEPLOY.md`](docs/DEPLOY.md)**，含各平台可直接抄的壳代码。

| 目标 | 做法 |
|---|---|
| 静态网站 | 上传 `index.html` + `style.css` + `src/`，无需构建 |
| Cloudflare Pages | `npx wrangler pages deploy games/resonance` |
| GitHub Pages / Netlify / Vercel | 目录当根发布，构建命令**留空** |
| iOS | WKWebView 壳 + `RESONANCE` messageHandler |
| Android | WebView 壳 + `RESONANCE_NATIVE` JavascriptInterface |
| 鸿蒙 NEXT | ArkWeb + `javaScriptProxy`（协议与安卓完全相同） |
| 微信小游戏 | `web-view` 内嵌，或 canvas 适配层 |
| AppLovin MAX | 原生壳注入，频次仍由游戏侧硬编码控制 |

跨平台差异全部收在 **`src/platform.js`** 一个文件里。业务代码只认识
`Platform.*`，不认识 `wx`、不认识 `webkit`。**新增一个平台 = 新增一个 adapter。**

桌面浏览器上可以强制走某个分支来调试：

```
?platform=wechat    ?platform=native    ?platform=web
```

## 文件结构

```
index.html          全部 UI 结构
style.css           CRT 磷光 + 石墨面板视觉
src/
  platform.js       跨平台适配层 (Web / 微信 / 原生壳)
  rng.js            可复现随机数 (xmur3 + mulberry32, 按用途分流)
  icons.js          44 个手绘 SVG 图标 (29 遗物 + 15 UI)，无 emoji
  relics.js         29 件遗物 + 真实音乐史典故
  audio.js          程序化五声音阶音效，零音频文件
  game.js           纯逻辑，零 DOM 依赖 —— 可以直接在 node 里跑
  render.js         canvas 渲染与演出
  main.js           UI 绑定与流程
docs/
  DEPLOY.md         部署手册（各平台壳代码）
  benchmark.js      数值实测脚本
  model.js          商业模型
```

`game.js` 零 DOM 依赖不是巧合，是为了让它能在 node 里被大批量模拟——
下面的所有数字都靠这一点。

## 测试与可复算

```bash
npm install          # 只为测试; 部署不需要
npm run test:logic   # 124 项: 逻辑 / 平衡 / 商业化底线 / 终局 / 终章
npm run test:dom     # 73 项: jsdom 里真实 DOM 交互 + 模糊测试 + 无障碍
npm run test:layout  # 7 种视口布局校验
npm run shots        # 截图 + 控制台错误检查（需先 npm start）
```

游戏里对玩家宣称"实测分布 · 可复算"，所以那句话必须是真的：

```bash
node docs/benchmark.js    # 复算 BEAT_PCT / STREAK_GRACE / 调音师阈值
node docs/model.js        # 商业模型: 内容深度 / 留存 / LTV / 敏感度
```

两个脚本都是**确定性**的（固定种子基），任何人 clone 下来跑一遍应该
得到 `src/game.js` 里那张表。`benchmark.js` 还会自检漂移并在不一致时警告。

> 顺带一提，`BEAT_PCT` 最初是手写的，实测发现最大偏差 19 个百分点。
> 现在表里的数字是 `node docs/benchmark.js percentile` 的直接输出。
> 显示的百分位封顶 99——深层关卡四舍五入会到 100%，但玩家此刻正站在
> 这一关，屏幕上写"100% 的对局走不到这里"是自相矛盾的。

## 商业模型说了什么

`docs/model.js` 是一个可运行的模型，规矩是：**凡是能从代码里测出来的量一律测，
不许填**。内容深度、掌握曲线、单局时长全部由真实游戏跑出；只有市场侧
（eCPM、付费率）必须外部假设，那些统统标 `ASSUMED` 并逐一做敏感度分析。

几个实测结论：

* **构筑空间**：60 局出现 56 种不同构筑；C(29,6) ≈ 4.8×10⁵ 种组合。玩家不可能"看完"。
* **掌握曲线**：技巧 0.25 → 0.90，中位关卡 2 → 15（**7.5 倍**）。技巧持续变现，没有提前封顶。
* **敏感度**：决定成败的是**核心玩家占比**与**核心留存时间常数**（弹性 0.89 / 0.79），
  而不是 eCPM 或付费率（0.15 / 0.07）。

最后一条是这个项目最重要的结论：**该死磕的是内容深度和公平性，
而不是变现技巧**。这恰好和"挨骂尽量少"是同一个方向，不是两难。

### 关于收入目标，模型给的是不修饰的答案

按测算的税后净利 ≈ $1.19/用户：

| 两年税后净利 | 需要累计装机 | 判断 |
|---|---|---|
| $1 亿 | ≈ 8,400 万 | 有先例（Vampire Survivors / 羊了个羊）——**很难但真实可达** |
| $10 亿 | ≈ 8.4 亿 | Block Blast 级，全球前十，需长期买量与多年运营 |
| $100 亿 | ≈ 84 亿 | **超过地球上任何单款休闲游戏的历史记录——不可达** |

一个只会输出"能成"的模型不是模型，是自我安慰。所以它必须能说出第三行。

可执行的结论：**把目标定在做到第一档并具备复制能力，而不是赌单款奇迹。**
理由就在敏感度里——决定成败的是内容深度，而内容深度是**可复用的资产**：
一个能做出高核心留存的团队，做第二款第三款时仍然拥有它；
靠买量堆装机的团队，每一款都得重新买。

十位数收入的现实路径不是一款游戏赚百亿，而是一套能反复做出高留存的方法论。
本作是它的第一次验证。

## 一些实现上的取舍

**为什么棋盘尺寸由 JS 决定而不是 CSS**：棋盘必须是正方形，且要同时受
宽度和高度约束。纯 CSS 解不了这个双向约束（`aspect-ratio` 只能单向让步），
所以 `render.js` 里由 JS 算出边长再写回 CSS 自定义属性。
高瘦屏幕上剩余的竖向空间会通过 `--pcell` 换成更大的手牌方块，
而不是留一块 100+px 的空白。

**为什么没有 emoji**：emoji 的字形由系统决定，同一个字符在不同平台上
是不同的画。UI 的 15 个图标和 29 件遗物图标全部是手绘 SVG。
色盲辅助字形也全部取自 Geometric Shapes 区块（U+25A0–U+25FF），
避免某些平台把它们提升成彩色 emoji——那会让字形无法跟随颜色，
辅助功能反而失效。`test-dom.js` 有一条正则测试守着这件事
（它抓到过一个我肉眼漏掉的 `★`）。

**为什么遗物有真实典故**：Gros Michel / Cavendish 的手法——真实的历史
让机制变得可记忆。29 件遗物的 flavor 全部来自真实音乐史，且有测试
保证它不与规则描述重复、不含营销腔。

## 已知的设计问题

诚实记录。

### 已解决：熟练玩家的单局可以无限长

技巧 0.9 档有 27/40 局撞到 3000 落子的模拟上限而非死亡——一局长到测不
出来。对留存是好事（远没玩腻），但缺少一个体面的"收尾"：那种"永远赢不了、
只能等自己失手"的体验会把最投入的玩家熬走，他们付出最多，却唯一拿不到
一个句号。

现已加入**终章**（第 18 关，实测定点见上）。刻意做成横幅而不是弹窗、
也不强制结束对局——通关是荣誉标记，不是闸门。通关记录落在三处：结算页
徽章、主菜单通关次数、分享文本标记。

仍然存在的取舍：单局时长对高手依然没有硬上限，所以按"局数"计费的广告
模型在这批玩家身上收益偏低。`docs/model.js` 的广告模型因此**按时长而非
局数**建模，这不是绕过问题，而是承认它。

### 未解决：付费点仍然很薄

激励视频只允许出现在提示/刷新两处（硬编码白名单，`test.js` 钉住），
IAP 只有去广告与外观。这是"挨骂少"换来的代价：ARPPU 与付费率都低，
`docs/model.js sensitivity` 显示二者的弹性仅 0.07——也就是说这条线
再怎么调都撬不动大盘。收入的杠杆全部压在留存与 eCPM 上（弹性 0.79~0.89）。
